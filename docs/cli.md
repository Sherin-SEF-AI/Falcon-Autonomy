# Command line

`falcon` (or `python3 -m falcon_autonomy`) runs every heavy action headless, on the same code paths as the GUI: the
same configs, job queue (with the machine-wide CARLA lock and memory guard), workers and protocol.

| command | what it does |
|---|---|
| `falcon [gui] [PROJECT]` | the application |
| `falcon --mcp [--mcp-project FILE] [--mcp-mode auto\|window\|file]` | Falcon as an MCP server on stdin and stdout for Claude Code or another MCP client: the assistant's read and act tools in the open window (through a token-protected bridge on 127.0.0.1, one undo step per call) or on a project file (each act call saved, the file backed up first); trash and the never-list refused ([MCP](mcp.md)) |
| `falcon doctor` | checks CARLA, its Python, the GPU, the Vulkan driver, memory, systemd-run and Falcon's ports; suggests the low_vram profile on a GPU with 9 GB or less; lists the optional hardware-in-the-loop pieces (vcan, v4l2loopback, linuxptp), none of them required |
| `falcon project new NAME PATH` | a new project file |
| `falcon project validate PATH` | checks a project against its schema (migrating in memory) |
| `falcon project migrate PATH` | migrates a project to this build's format, in place |
| `falcon probe [--wait S]` | what server answers on Falcon's port (starts Falcon's server if none) |
| `falcon smoke PROJECT` | the 30 s smoke drive; records this machine's throughput |
| `falcon drive PROJECT [--world ID] [--rig ID] [--seconds S] [--fps F] [--seed N] [--out DIR] [--max-wall S] [--triggers all\|none\|ID,…]` | a recorded drive (with the project's trigger rules for drives unless `none`) |
| `falcon triggers list\|check PROJECT [--json]` · `add PROJECT "when … -> …" [--id ID] [--repeat once\|every\|cooldown] [--cooldown S] [--applies drives,scenarios,live] [--disabled]` · `remove PROJECT ID` · `signals` | live trigger rules: list, validate (exit 2 on a problem), add, remove; the signals and actions ([scenarios](scenarios.md#trigger-rules)) |
| `falcon tidy` | tidies Falcon's server after a killed worker |
| `falcon reproduce RUN [--into DIR] [--pose-tol M] [--rgb-tol L]` | re-runs a run from its input and compares |
| `falcon runs PROJECT [--rebuild]` | lists a project's runs (re-indexing the workspace) |
| `falcon sweep PROJECT --scenario S --name N [--grid K \| --samples K] [--seed N] [--world W] [--rig R] [--on local\|cluster\|cluster:POOL]` | a scenario sweep (a study; resumable); `--on` sends its drives to the compute nodes while the study runs here ([cluster](cluster.md)) |
| `falcon search PROJECT --scenario S --name N [--method bayes\|bayes-pof\|cmaes\|cem\|adaptive\|random] [--budget B] [--batch K] [--threshold T] [--objective criticality\|perception\|both --model ID] [--objective robustness (--stl FORMULA \| --rule SET:ID) [--scale S] [--smooth β]] [--weather FIELD[:LO:HI]] [--metric M] [--fps F] [--search-seed N] [--count avoidable\|all] [--no-feasibility] [--on WHERE]` | a rare-case search in a study (resumes, and starts from its sweeps); by default the criticality objective counts only failures the ego could have avoided by RSS, over the kinematically feasible part of the parameters ([scenarios](scenarios.md#avoidable-failures-responsibility-sensitive-safety)); `--objective robustness` searches for a violation of a signal-temporal-logic requirement by σ(−ρ/scale), and `cem` is the cross-entropy method ([falsification](falsification.md)); `--on` as for sweeps |
| `falcon scenario from-text PROJECT "DESCRIPTION" [--world W] [--rig R] [--seed N] [--rounds 2] [--offline] [--model M] [--apply] [--run] [--fake-carla DIR] [--json]` · `check RUN ["DESCRIPTION"] [--claims FILE] [--model] [--json] [--no-write]` | a scenario written from a description in words — by the assistant's model (only text is sent; validated against the scenario schema and repaired from its errors in up to two rounds) or drafted offline from the phrases Falcon recognises — added and run once; a run checked against a description claim by claim (actor kinds, manoeuvres, a speed breaker or junction within N m, light, weather, the ego's speed, the outcome): met, not met or not checkable with the measured value; `check` exits 1 when a claim is not met ([a scenario from a description](scenario-text.md)) |
| `falcon failrate run PROJECT --scenario S [--stage-size N] [--final N] [--max-stages K] [--judge objective\|checks\|rules\|stl] [--stl FORMULA \| --rule SET:ID] [--exposure-per km\|hour --encounters X --exposure-source TEXT] [--on WHERE] [the search's options]` · `show STUDY\|PROJECT --name N` · `check [--p 1e-4,1e-6] [--dims 2,5] [--problems tail,corner] [--seeds N]` | a scenario's failure probability per encounter with a 95 % interval by adaptive importance sampling (resumable study `studies/rate-…`), per 10ⁿ km or hours with your encounter rate; refused when too few effective failures; `--judge stl` counts a violation of the requirement (ρ < 0) as the failure; `check` validates the estimator on problems with a known probability ([failure rate](failure-rate.md)) |
| `falcon coverage show PROJECT [--rows D --cols D] [--target 0.05] [--confidence 0.95] [--cells] [--json]` · `fill PROJECT [--max N] [--kind search\|sweep] [--budget N] [--apply] [--run]` | the operating domain's grid (weather × road × actor × speed × light): runs, failures and status per cell under the Clopper–Pearson rule; a scenario and a search (or sweep) per untested or under-sampled cell ([ODD coverage](odd-coverage.md)) |
| `falcon rules check RUN... [--set india\|generic\|FILE] [--out DIR]` · `falcon rules list\|show\|signals` | checks recorded runs (or an episodes.jsonl) against traffic rules written in temporal logic: robustness, violation intervals, counts per km ([traffic rules](traffic-rules.md)) |
| `falcon experiment active --id ID --pool SRC... --test SRC [--strategies entropy,margin,kcenter,hybrid] [--rounds R] [--budget B] [--seeds K] --workspace W` | active learning: which frames to add, against random selection with paired intervals ([active learning](active-learning.md)) |
| `falcon generate plan\|new PROJECT --id ID [--spec FILE] [--model M --world W --rig R --conditions c1,c2 --rounds N --budget-drives N --budget-frames N --max-cells K]` · `run PROJECT --id ID [--rounds N]` · `show\|list PROJECT [--id ID] [--json]` | generation rounds: class × condition cells ranked by expected value, drives and scenario runs generated for the best within a budget, the detector retrained and compared per cell on a held-out set fixed before round 1 (resumable; stops when no chosen cell improves; [generating data](generation.md)) |
| `falcon recon train\|from-dashcam\|place\|eval\|render\|rerender\|hybrid\|hybrid-drive\|closedloop\|info …` | neural reconstruction of a recorded drive (3D Gaussian Splatting: Triton kernels on a CUDA GPU, pure PyTorch elsewhere): train, pose and reconstruct a dashcam segment (visual odometry + its GPS), place a posed segment on a world imported later, held-out and novel-view quality, render a pose, re-render the drive along a shifted path, composite CARLA's actors over it (a hybrid world: a recorded drive, or a new CARLA drive of its path with seeded traffic and the ego moved sideways) ([reconstruction](reconstruction.md)) |
| `falcon recon train … --dynamic [--lidar] [--camera all\|A,B]` · `from-dashcam … --dynamic [--tracks PATH]` · `render RECON … [--camera pinhole\|fisheye --fisheye-fov 190 --fisheye-model M --fisheye-size WxH --fisheye-method cube\|lens] [--lidar] [--radar]` · `eval RECON --lidar [--warp-shift M]…` · `closedloop RECON --policy P --out DIR [--episodes N] [--deviate 3.0] [--seed N] [--obs-size WxH] [--start S] [--lateral M]` | 4D reconstruction: tracked road users learned as actors in their box frames (a Falcon run's actors, nuScenes annotations, or with `--tracks` the road users the dashcam ingest tracked in the segment), turning and steering wheels, deforming pedestrians, a neural lidar with ray drop; fisheye renders by cube faces or the lens fast path, geometric radar; a policy driven through the reconstruction in closed loop as ordinary Falcon runs, ended where it leaves the trust envelope ([reconstruction](reconstruction.md#moving-actors-a-neural-lidar-fisheyes-and-closed-loop-4d)) |
| `falcon worldmodel train\|eval\|imagine\|collect\|e2e\|e2e-offline\|show …` | a learned world model (RSSM) on drives and episodes, scored against copy-last and constant-velocity baselines per horizon; policies learnt in its imagination; end-to-end camera policies ([world-model training](world-model-training.md)) |
| `falcon adversary train\|eval\|replay …` | learned adversarial traffic under realism constraints against a fixed ego; failure rates against random and scripted baselines; replays ([adversarial traffic](adversarial-traffic.md)) |
| `falcon vlm list\|fetch\|verify\|eval\|finetune …` | vision-language models scored against the simulator's truth (accuracy, grounding, hallucination, faithfulness); approved downloads only ([vision-language](vlm.md)) |
| `falcon deploy check\|calibrate\|build\|profile\|accuracy\|gate\|report\|all …` | TensorRT engines (FP32/FP16/INT8, GPU or DLA) built and profiled on the Jetson AGX Orin — latency, power and energy from its rails, accuracy against the host's ONNX model with paired intervals — and a release gate; a labelled simulated device (onnxruntime on this host) for the pipeline only ([deploy](deploy.md)) |
| `falcon why case PROJECT --run RUN --out DIR [--failure F] [--model ID] [--actor A \| --track N] [--step S]` | why a scenario run failed: counterfactual re-runs, one factor at a time ([root cause](root-cause.md)) |
| `falcon why evaluation EVAL --out DIR` | the correlates of an evaluation's misses, with intervals |
| `falcon why episode PROJECT --episodes FILE --episode N --policy P --out DIR` | a Leaderboard infraction by the policy's inputs |

| `falcon v2x junctions PROJECT --world W [--json]` · `place PROJECT --world W (--junction J [--corner K] \| --at X,Y[,YAW]) [--preset pole-camera\|intersection-lidar\|camera-lidar] [--height H]` · `list` · `remove PROJECT RSU` | roadside units: an imported world's junctions as candidates (signalised first, named after the OSM ways meeting there), a pole at a corner clear of the driving lanes, the project's poles ([V2X](v2x.md)) |
| `falcon v2x drive PROJECT --rsu RSU [--rig R] [--seconds S] [--seed N] [--vehicles N] [--walkers N] [--start-min M --start-max M] [--record-every N] [--out DIR]` | a recorded drive whose ego starts 50–150 m from the pole heading towards it, the traffic placed around it first |

Commands that need CARLA start Falcon's own server when none is running and stop it at the end (`--keep-server`
leaves it running). Ctrl+C cancels the job politely — the worker tidies the server — and a second Ctrl+C kills it.

## Exit codes

`0` ok. Otherwise the worker's code — `1` crashed, `2` failed, `3` cancelled, `4` server lost, `5` no server, `6`
refused, `7` no carla (see [the protocol](protocol.md#exit-codes)) — or `2` for a usage error or a project that does
not validate. `falcon reproduce` exits `2` when the re-run does not agree within the tolerance. `falcon ci run` follows
a test runner's convention instead: `0` every gate passed, `1` a gate failed, `2` an error (no verdict), `3` cancelled
([CI mode](ci.md#exit-codes)). `falcon gsn verify --gate` exits `1` when a top goal is red (with `--fail-on amber`,
also when one is amber); `falcon backend check` exits `2` when the folder is not the backend's, and `falcon profile
measure` when the peak is above its limit.
